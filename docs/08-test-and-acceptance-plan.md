## 1. 验收原则

高风险流程必须同时满足：业务语义正确、数据库原子性正确、密码学材料不泄露、浏览器交互可完成、故障后结果可解释。单个接口返回 200 不能视为流程验收通过。

所有测试记录：提交版本、数据库迁移版本、测试时间（北京时间显示、UTC 存储）、环境、请求关联 ID、测试数据命名空间、预期结果、实际结果和失败证据。

## 2. 测试环境

| 类型 | 环境 | 数据规则 |
|---|---|---|
| 单元/密码学 | Node test runner | 固定测试向量，不接真实 SMTP 或外部 S3 |
| 集成 | Docker Compose + PostgreSQL + 默认文件卷 + Mailpit；S3 profile 增加 MinIO | `test` 命名空间，自动清理 |
| 端到端 | staging Chromium 移动/桌面视口 | 白名单邮件、独立对象前缀、不可写正式地址 |
| 安全 | staging/隔离临时环境 | 不使用正式密码、邮箱、ZIP 或 Secret |
| 性能 | staging 资源规格 | 使用合成 ZIP 和模拟用户，不触发正式发布 |

## 3. 测试矩阵

### 3.1 领域和时间

- 北京时间自然日边界、跨月、跨年、夏令时不存在时区漂移；
- 阈值为 1、3、4、5、10 天时截止时间正确；
- 死亡门限 `ceil(N × 70%)` 与恢复门限 `floor(N ÷ 2) + 1`；
- 3/4/5/10 名联系人分别得到死亡 3/3/4/7、恢复 2/3/3/6；
- 同一自然日重复签到不生成第二条有效签到；
- 旧计划任务在新签到或阈值修改后无副作用退出。

### 3.2 状态机和并发

- SETUP → ARMED 的每个前置条件缺失都被阻止；
- 死亡确认、主密码恢复和发布流程不能并发；
- 两个联系人同时达到门限只产生一个第二阶段和一组提醒任务；
- 否定确认与肯定门限并发时只产生一个终态，否定按产品优先级处理；
- 管理员终止与 24 小时到期发布并发时只有一个成功结果；
- `release_at <= now` 或 `publish_locked_at` 已存在时终止永久拒绝；
- 第二阶段后所有联系人决定接口返回阶段关闭错误。

### 3.3 密码学和文件

- Argon2id 参数、Unicode 密码、密码上限和弱密码拒绝；
- 密码 NFC/UTF-8 规范化、512 字节上限、不得 trim/大小写折叠，以及 pepper 版本轮换和成功登录后重哈希；
- 数据库泄露、私有桶泄露且无用户密码时不能解密 ZIP；
- 少于门限的任意分片不能重建 `VK`；达到门限的任意有效组合可以重建；
- 死亡分片与恢复分片、不同代次、不同联系人和不同用途不能混用；
- 分片代次公开验证证明必须绑定当前 `vkCommitment`；篡改承诺、联系人、代次、用途或索引均被拒绝；
- 初始化、联系人注册、普通改密和重分片的包装证明必须绑定正确密码、主体、`VK`/私钥和 AAD；错误绑定不能进入 `ARMED`；
- 联系人改密后旧密码不能解开私钥，新密码可解开且历史分片仍可用；
- secretstream 的损坏、截断、乱序、错误头和缺少 `TAG_FINAL` 均被拒绝；
- ZIP 路径穿越、绝对路径、符号链接、重复规范化路径、ZIP bomb 和 ZIP64 异常值均被拒绝；
- `will.md` 必须是根目录唯一精确文件，大小上限和 Markdown 清洗规则有效；
- 公开 ZIP、公开 HTML 和公开审计摘要与发布记录一致。
- 上传完成时服务端重新计算真实对象大小和 SHA-256；客户端伪造摘要或 manifest 不能进入 `READY`。

### 3.4 API、权限和隐私

- 未认证、OWNER、CONTACT、PUBLIC、WORKER、MIGRATOR 角色矩阵逐路由验证；
- 联系人不能枚举其他联系人、流程明细、邮箱或私有审计；
- 公开接口不返回 IP、User-Agent、联系人身份、SMTP 错误或内部对象键；
- CSRF、Origin、Fetch Metadata、Cookie 属性和重新认证均有自动化测试；
- 令牌只存 HMAC，URL Fragment 入口被消费后立即清除；
- 主密码恢复只向主邮箱发送启动链接和验证码；验证码 8 位、10 分钟有效、最多 5 次，错误不能通过换 IP 重置；链接或验证码单独存在均不能建立重包装会话；
- 日志、异常、任务参数和响应体不包含密码、Cookie、令牌、密钥、分片或遗书正文；
- 重复幂等键返回原结果，载荷不一致返回 `409`；
- 未知 JSON 字段、批量赋值和未声明 OpenAPI 路由均被拒绝或 CI 阻断。

### 3.5 邮件、任务和故障

- 主邮箱明确失败立即回退备用邮箱；
- 首次发送 + 7 次重试的时间序列准确，重启不重复投递；
- SMTP 暂时不可用不阻塞公开发布；
- `RELEASE_STAGE_KEK` 与 `RECOVERY_STAGE_KEK` 的容器读取权限严格隔离，错误权限配置拒绝启动；
- Worker/API/PostgreSQL/文件存储重启后任务和状态可继续；可选 S3 profile 同样验证；
- 发布解密失败后保持 `publish_locked_at`，不恢复取消权限；
- 测试邮件强制 `【测试】` 前缀和白名单；
- 测试对象、审计、邮件和状态不能进入正式空间。

### 3.6 页面、无障碍和兼容性

- 320px、390px、768px、1280px 视口下无横向溢出；
- 200% 缩放、键盘、触屏和屏幕阅读器可完成关键流程；
- 关键按钮至少 44×44px，状态不只依赖颜色；
- 中文输入法可完成确认文字；确认文字禁止粘贴，但密码允许密码管理器填充；
- 倒计时由服务端时间初始化和校准，客户端不能推进状态；
- 401/403/409/423/422/429/5xx、空数据、离线、加载和重试状态均有可操作文案；
- 页面不渲染硬编码演示数据，不使用无意义的 `href="#"`。

## 4. 性能目标

- 非上传/下载 API 服务端 P95 小于 500ms，密码 KDF 操作单独记录；
- Worker 截止扫描在目标窗口内完成，任务积压可在健康页观察；
- 上传/下载按部署容量、并发和带宽限制测试；
- 公开 ZIP 下载限流不会阻塞管理员签到和关键状态接口。

## 5. 安全评审

上线前必须获得以下评审记录：

1. 应用密码学专家评审浏览器端密钥协议、Shamir 分片和密钥生命周期；
2. 后端评审数据库锁、条件更新、Outbox 和发布/取消竞争；
3. SAST、依赖漏洞、许可证、Secret、容器镜像和 SBOM 扫描；
4. 认证、越权、文件上传、业务逻辑、XSS、CSRF、SSRF 和路径穿越渗透测试；
5. 中国执业律师对知情书、隐私政策、遗嘱法律定位和实际部署范围的评审；
6. SMTP 沙箱、默认文件存储、可选 S3 适配器和重启恢复的实测记录。

## 6. 上线门禁

以下任何一项没有证据都不得把正式系统置为 `ARMED`：

- 迁移、角色授权、不可变触发器和健康检查通过；
- 所有关键 PRD 验收场景通过；
- 密码学、ZIP、并发、权限和日志泄露测试通过；
- 16 个已有页面与新增页面的加载、错误态、无障碍验收通过；
- 最终邮件不带 ZIP，邮件失败不阻塞发布；
- `RELEASED` 没有普通应用删除、替换、隐藏或取消路径；
- 测试模式白名单、对象前缀和公开地址隔离通过；
- 所有人工评审、风险确认和运行手册已归档；
- 生产镜像、依赖、迁移和 Secret 版本可追溯。
