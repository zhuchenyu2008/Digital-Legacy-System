## 1. 文档目的与约束

本文把静态设计稿转换为可实现、可测试的页面规格。设计稿中的姓名、邮箱、时间、版本号、摘要、人数和倒计时均为演示数据，不是产品默认值。

发生冲突时按以下优先级执行：

1. 已确认的产品需求与状态机；
2. 安全与隐私基线；
3. API、数据库和系统架构设计；
4. 本页面规格；
5. 静态 HTML 与截图中的示例文案或交互。

本文中的路由是前端实现建议；API 路径均省略统一前缀 `/api/v1`。页面只能使用中文界面。数据库继续使用 UTC 存储绝对时间，但所有页面和邮件必须显示北京时间。

## 3. 全局页面规则

### 3.1 会话、权限与状态

- `/admin/**` 首次渲染前调用 `GET /auth/session`。未登录跳转管理员登录页，非管理员返回 403 页面，不短暂显示私有数据。
- 联系人使用独立联系人会话，不能访问 `/admin/**`，也不能从任何响应枚举其他联系人。
- 页面状态必须来自服务端。客户端不能根据本地缓存或本地时钟自行推进 `DEATH_CONFIRMING`、`RELEASE_PENDING` 或 `RELEASED`。
- 管理员在活动流程期间打开联系人或文件编辑页时，页面可展示快照数据，但必须禁用变更操作并解释锁定原因。
- 认证 Cookie、入口令牌、密码、密钥和分片不得写入 `localStorage`、URL 查询参数、日志或分析事件。

### 3.2 时间与倒计时

- 页面统一显示 `YYYY-MM-DD HH:mm:ss（北京时间）`；相对时间只能作为辅助信息。
- `RELEASE_PENDING` 倒计时由 `releaseAt - serverNow` 初始化，定期调用 `GET /public/status` 或当前流程接口校时，切换后台再返回时立即校时。
- 倒计时归零只改变前端展示为“正在发布”，不能自行宣告发布成功；必须等服务端返回 `RELEASED`。
- 屏幕阅读器不应每秒播报倒计时。默认每分钟播报一次，最后一分钟可提高到每 10 秒一次，归零时播报状态变化。

### 3.3 表单与高风险操作

- 所有修改请求携带 CSRF 令牌；联系人决定、包激活、流程终止等请求按 API 要求携带 `Idempotency-Key`。
- 密码字段允许密码管理器填充，不显示明文，不在校验错误中回显。只有法定确认文字需要阻止复制、粘贴、拖放和自动填充。
- 保存、高风险操作和上传必须有 `idle`、`submitting`、`success`、`error` 状态。提交期间防止重复触发，但网络失败后允许使用同一幂等键安全重试。
- 错误信息使用用户可行动的中文说明，并保留可复制的 `requestId`；不得直接显示后端堆栈、密钥信息或 SMTP 密码。
- 长按、拖拽和悬停只能作为增强交互，必须同时提供键盘和触屏可完成的等价操作。

### 3.4 响应式与无障碍

- 小于 `768px` 使用移动布局，主要操作保持至少 `44 × 44px` 点击区域；桌面内容最大宽度遵循视觉规范的 `1024px` 阅读区。
- 移动端不得设置 `user-scalable=no`，必须允许系统缩放。
- 图标按钮必须有中文可访问名称；不能只用颜色区分 `ACTIVE`、`PENDING_KEYING`、错误或选中状态。
- 表单具备可见标签、字段级错误、错误摘要和合理焦点顺序。异步结果通过低频 `aria-live` 区域通知。
- 移动底栏与桌面顶栏是同一路由体系；当前项同时用语义属性 `aria-current="page"` 标记。

### 3.5 通用加载、空数据与失败状态

| 状态 | 页面行为 |
|---|---|
| 首次加载 | 保留页面骨架与标题，使用骨架屏；不得先渲染演示数据 |
| 无数据 | 解释原因并给出唯一主要下一步，例如“尚未邀请联系人”或“尚未上传 ZIP” |
| 401 | 清除仅内存态，跳转对应登录页，并保留安全的站内返回路径 |
| 403 | 显示权限不足或需要重新认证；不得改写为 404，资源隔离接口除外 |
| 409/423 | 刷新服务端状态，解释不可逆、并发更新或流程锁定原因 |
| 422 | 把业务校验错误关联到字段或前置条件，不丢失用户尚未提交的输入 |
| 429 | 显示可再次尝试的时间，不自动高频重试 |
| 5xx/离线 | 保留已加载的非敏感内容，提供手动重试；不得假装操作成功 |

## 4. 联系人管理

### 4.1 页面 01：联系人管理（移动端）

**目标与布局**

- 390px 设计稿使用单列布局：状态栏、页面标题、门限摘要、联系人列表、邀请按钮和固定底部导航。
- 门限摘要只统计 `ACTIVE` 且已纳入当前分片代次的联系人。`INVITED` 与 `PENDING_KEYING` 不计入总有效人数。
- 联系人卡片显示姓名、邮箱、中文状态与可用操作。设计稿中的 `PENDING` 实现时统一显示为“待分片”，领域值为 `PENDING_KEYING`。

**数据与接口**

- `GET /owner/contacts`：联系人、邀请、同意版本和分片状态。
- 页面根据有效人数 `N` 显示死亡确认门限 `ceil(N × 0.70)` 和恢复门限 `floor(N ÷ 2) + 1`；服务端结果是最终依据。
- 行操作使用 `POST /owner/contacts/{contactId}/invitation/resend`、`POST /owner/contacts/{contactId}/password-change-invitation` 与 `POST /owner/contacts/{contactId}/remove`。

**交互与验收**

- 点击“邀请新联系人”打开全屏抽屉，必填唯一姓名与有效邮箱；成功收到 202 后显示“邀请发送中”，不假定邮件已投递。
- `INVITED` 可重发邀请；`ACTIVE` 可发送密码修改邮件；删除必须二次确认。删除活动联系人还必须输入主密码并在同一流程内完成新分片代次。
- 活动死亡确认或密码恢复流程期间，邀请、删除、重发和重新分片全部禁用，并显示“当前流程已锁定联系人名单”。
- 操作菜单可通过点击、键盘 Enter/Space 和屏幕阅读器访问；焦点关闭后回到原联系人卡片。

### 4.2 页面 02：联系人管理（桌面端）

**目标与布局**

- 1280px 设计稿使用顶栏、门限摘要、规则说明和联系人数据表。移动卡片与桌面表格使用同一数据源与操作权限。
- 表格列为“姓名与邮箱、状态、知情同意、操作”。列标题使用真实 `<th>`，状态徽标同时带文本。
- 长列表使用服务端游标分页或渐进加载；分页后仍保持筛选、焦点和返回位置。

**交互与验收**

- 邀请、重发、密码修改邀请、删除和重新分片规则与页面 01 完全一致。
- “已签署”必须显示真实知情书版本；未注册联系人显示“待签署”，不能笼统继承其他行的版本。
- 删除后有效联系人将少于 3 人时，在提交前说明风险，服务端返回 `422 DLS-CONTACT-MINIMUM` 时不得从表格移除该联系人。
- 任何人数变化后重新拉取联系人集合与门限，不在客户端对旧列表做乐观门限计算。

## 5. 文件管理

### 5.1 页面 03：文件管理（桌面端）

**目标与布局**

- 1280px 设计稿包含本地加密提示、拖拽/选择区、`will.md` 预览、当前版本、安全校验和历史摘要。
- 支持拖拽与文件选择；拖拽区必须可聚焦，并提供等价的“选择 ZIP”按钮。

**上传与激活流程**

1. 浏览器验证文件为 ZIP，根目录存在且仅存在大小写精确的 `will.md`；禁止路径穿越、绝对路径、符号链接和 ZIP 炸弹风险条目。
2. 在浏览器安全解析并清洗 `will.md` 预览，禁用 Markdown 原始 HTML；预览不代表服务器已接受。
3. 调用 `GET /owner/vault/material`，在浏览器分块加密，不上传明文 ZIP、明文密钥或明文清单。
4. 依次调用 `POST /owner/packages/uploads`、分段上传和 `POST /owner/packages/{packageId}/complete`。
5. 完成后进入 `READY`，管理员输入主密码后调用 `POST /owner/packages/{packageId}/activate` 原子激活。

**状态与验收**

- 上传状态至少包括：本地校验、加密、上传百分比、服务端校验、待激活、已激活、失败与可重试。
- 激活按钮仅在包为 `READY`、客户端材料完整且当前无活动流程时启用。`423 DLS-PACKAGE-LOCKED` 后保留新包但不替换活动版本。
- `GET /owner/packages` 提供当前版本和历史元数据。历史版本只保留版本号、密文摘要、时间和审计记录；旧密文已删除，不提供下载或恢复按钮。
- 页面时间必须转换为北京时间。设计稿中的 `UTC` 和示例摘要只用于视觉占位。

### 5.2 页面 07：文件管理（移动端）

**目标与布局**

- 390px 设计稿把上传、预览、活动版本和历史版本改为单列卡片；业务规则与页面 03 完全一致。
- SHA-256 可换行并提供“复制摘要”按钮，复制成功通过非阻塞提示反馈。

**交互与验收**

- 移动浏览器可从文件选择器选取 ZIP；选择后先展示文件名、大小和移除入口，再开始加密。
- 加密或上传期间阻止误离开；如浏览器确实中断，不宣称支持后台上传，重新进入后根据服务端上传状态决定继续或中止。
- 设计稿中的“最大 50MB”和“必须包含证明文件”不是已确认产品规则。容量以部署返回限制为准，唯一强制内容是 ZIP 根目录中的 `will.md`。
- 不得使用禁止缩放的 viewport 配置。

## 6. 设置

### 6.1 页面 04：设置（移动端）

**目标与布局**

- 390px 设计稿按“个人资料、核心配置、SMTP 服务、安全与审计”分组；点击设置项进入抽屉或子页面编辑。
- 系统时区固定为 `Asia/Shanghai`，只能查看，不能修改。

**数据与接口**

- `GET /owner/settings`：管理员资料、未签到阈值和只读配置状态。
- `PATCH /owner/settings`：修改显示姓名、主/备用邮箱与未签到阈值，提交时要求主密码重新认证。
- `PUT /owner/smtp-settings`：保存 SMTP；密码/API Key 只写不读，页面只能显示“已配置”掩码。
- `POST /owner/smtp-settings/test`：向主邮箱、备用邮箱或测试白名单发送测试邮件。
- `POST /owner/arm`：满足全部前置条件后确认不可撤回风险并启用。

**交互与验收**

- 邮箱修改实时校验格式、唯一性及主/备用邮箱不能相同；阈值只接受正整数，并明确修改可能立即触发确认流程。
- SMTP 测试结果区分“请求已接受”“投递成功”和“最终失败”，不能把入队显示为已送达。
- 不可撤回风险不能用一个预先开启的视觉开关代替。必须显示完整说明、要求输入指定确认文字与主密码，并由 `POST /owner/arm` 校验。
- 设计稿中的“重置系统”没有产品与 API 授权，当前版本不得实现或展示可操作入口；尤其不得提供绕过 `RELEASED` 不可逆约束的数据清除功能。

### 6.2 页面 06：设置（桌面端）

**目标与布局**

- 1161px 设计稿使用分区表单与页面级“取消更改/保存配置”；字段规则与页面 04 相同。
- 初始值来自服务端，未修改时保存按钮禁用；取消恢复最后一次服务端快照，不触发网络写入。

**交互与验收**

- 保存前先显示变更摘要；姓名、邮箱、阈值或 SMTP 敏感项修改需要最近 5 分钟重新认证，不满足时打开主密码验证对话框。
- SMTP 密码的掩码值绝不能作为真实值再次提交；用户未填写新密码时请求表示“保持不变”。
- 设置保存成功后重新获取 `GET /owner/settings`，显示服务端规范化结果和新的签到计划。
- “修改主密码”当前缺少普通改密 API 契约；在接口补充前不得接入伪操作。可以隐藏该按钮或明确标记为未开放，不能错误复用门限恢复接口。
- 页脚 Legal、Privacy Policy、Audit Log 必须连接真实内容；无对应页面时不使用 `href="#"`。

## 7. 管理员首页

### 7.1 页面 08：管理员首页（移动端）

**目标与布局**

- 390px 设计稿突出剩余时间和签到主操作，底部提供首页、联系人、文件、设置导航。
- 页面仅供已认证管理员使用，可显示私有签到信息；不能把该视图当作未认证首页。

**数据与接口**

- `GET /auth/session`：确认管理员会话和 CSRF 令牌。
- `GET /owner/check-in-schedule`：最后签到日、阈值、北京时间截止时间与提醒计划。
- `POST /owner/check-ins`：输入主密码完成签到。

**交互与验收**

- 点击主要签到按钮打开主密码输入区；正确提交后更新时间、重置倒计时并显示当天已签到。
- 设计稿中的指纹图标和“点击签到”只是视觉符号。当前需求未定义 WebAuthn 或生物识别，不能无密码签到。
- 若服务端返回存在已取消流程，页面必须明确告知“已终止确认流程并完成签到”；若已到发布锁定点则显示不可撤回错误。
- 页面进入 `DEATH_CONFIRMING` 或 `RELEASE_PENDING` 后跳转对应状态页；不能继续展示可误导的普通 ARMED 倒计时。

### 7.2 页面 10：管理员首页（桌面端）

**目标与布局**

- 1280px 设计稿显示系统状态、最后签到、下次截止、剩余时间、主密码签到、系统概况和最近审计。
- 状态、时间和摘要卡片在窄屏按页面 08 重排，不维护第二套业务逻辑。

**数据与接口**

- 签到计划使用 `GET /owner/check-in-schedule`；签到使用 `POST /owner/check-ins`。
- 当前包使用 `GET /owner/packages`，联系人摘要使用 `GET /owner/contacts`，审计使用 `GET /owner/audit-events?cursor=...`。
- 联系人概况需分别表达有效人数与总记录数，避免把设计稿的 `3 / 5` 误读成确认进度。

**交互与验收**

- 主密码字段使用 `autocomplete="current-password"`，提交后立即清空；失败不改变页面签到倒计时。
- 审计列表默认显示最近事件的北京时间、类型与结果，点击“查看全部”进入真实只读审计页。
- 审计、联系人和文件摘要加载失败不能阻止签到区域工作；各区块独立展示失败和重试状态。
- `SETUP` 状态显示未完成清单并引导到联系人、文件、SMTP 和风险确认，不显示虚假的 `ARMED` 徽标。

## 8. 第一阶段确认状态

### 8.1 页面 09：第一阶段确认（桌面端）

**页面性质**

- 1280px 设计稿对应未认证公开首页在 `DEATH_CONFIRMING` 时的状态视图，不是联系人作出决定的表单。
- 页面调用 `GET /public/status`，只展示开始时间、所需人数、已肯定确认人数和剩余人数。

**内容与交互**

- 主标题“生存状态确认中”，说明首次确认没有自动到期时间。
- 进度环使用 `approvedCount / requiredCount`，同时提供文本数值；门限规则表述为“肯定确认达到 `ceil(N × 70%)`”，不能写成“超过 70%”。
- “紧急联系人登录”进入联系人登录页；邮件入口令牌如存在只能从 URL Fragment 读取、立即清除后在请求体中解析。
- “管理员终止流程”进入管理员主密码验证，不使用生物识别。认证成功后由管理员终止接口完成取消与签到。

**隐私与验收**

- 公开页面不得展示联系人编号、逐人提交时间、加密身份占位符或私有审计链。设计稿中的 `联系人 #1/#2` 时间线应从公开实现移除。
- 页面状态徽标使用“确认中”，不能使用容易误解为正常状态的 `ARMED - 确认中`。
- `Cache-Control: no-store`，并设置真实响应头与 `<meta name="robots" content="noindex,nofollow,noarchive">`，而不是只在页面中显示提示文字。
- 状态变为 `RELEASE_PENDING` 或 `RELEASED` 时按服务端响应替换页面，不依赖手工刷新。

### 8.2 页面 11：第一阶段确认（移动端）

**目标与布局**

- 390px 设计稿将进度、说明、角色入口纵向排列；数据、权限与隐私规则和页面 09 完全一致。
- 主要入口顺序为联系人登录、管理员登录/终止；“操作手册”必须指向不泄露系统内部配置的公开说明。

**交互与验收**

- 进度环需有文本替代，不通过动画持续触发屏幕阅读器。
- 不展示私有审计时间线，不保留伪装成导航链接的无效按钮。
- 不得禁止页面缩放；长中文说明在 320px 宽度下不得横向滚动。
- 从邮件返回页面或应用切回前台时重新获取公开状态，已关闭的联系人操作显示 `DLS-CONTACT-ACTION-CLOSED` 对应说明。

## 9. 释放待定

### 9.1 页面 05：释放待定（移动端）

**页面性质与数据**

- 331px 设计稿是已认证管理员的最终 24 小时终止页，不是公开倒计时首页。
- `GET /owner/workflows/current` 提供工作流 ID、开始时间、`releaseAt` 和私有审计摘要；倒计时可用 `GET /public/status` 的 `serverNow` 校时。
- 页面只在 `RELEASE_PENDING` 且数据库时间早于 `releaseAt`、`publishLockedAt` 为空时允许终止。

**终止流程**

1. 管理员输入主密码；空值时长按按钮保持禁用。
2. 长按 3 秒提供有视觉和文本反馈的意图确认；指针离开、触摸取消、窗口失焦或按 Escape 时清零。
3. 调用 `POST /owner/workflows/{workflowId}/cancel`，请求体为主密码与 `OWNER_CONFIRMED_ALIVE`，并携带 `Idempotency-Key`。
4. 成功后清空密码、销毁客户端敏感材料，显示已通知联系人并跳转 `ARMED` 首页。

**状态与验收**

- 长按只提供操作摩擦，不能代替服务端密码验证、状态条件更新或幂等控制；键盘用户应有等价的“确认理解”后提交方式。
- `409 DLS-PUBLICATION-IRREVERSIBLE` 后立即禁用终止，显示“发布已锁定或完成，无法撤回”，继续轮询最终状态。
- 终止后的真实结果是返回 `ARMED`、记录签到和销毁临时密钥，不使用设计稿中含混的“锁定系统”。
- 私有审计接口失败不影响倒计时和终止入口；时间一律显示北京时间。

### 9.2 页面 16：释放待定（桌面端）

**目标与布局**

- 1280px 设计稿使用顶栏、警告区、大号倒计时、主密码终止区、私有审计和终止说明。
- 业务数据、终止步骤、幂等和不可逆处理与页面 05 完全一致。

**交互与验收**

- 桌面端支持鼠标长按、触屏、键盘与辅助技术，不把 `mousedown` 作为唯一入口。
- 倒计时每秒视觉更新，但按全局规则降低辅助技术播报频率；标签全部中文化。
- 浏览器多标签同时终止时只有首个满足条件的请求成功，其他标签根据 409 刷新最终状态。
- “查看完整不可篡改日志”进入管理员只读审计页；未实现审计页前不使用空链接。

## 10. 公开遗书

### 10.1 页面 12：公开遗书（桌面端）

**页面性质与数据**

- 1280px 设计稿是 `RELEASED` 终态的公开、无需登录页面。发布前 `GET /public/legacy` 返回 404，前端不得展示空壳遗书。
- `GET /public/legacy` 提供所有者显示姓名、发布时间、发布时固定并清洗的 `willHtml`、ZIP 大小、摘要和下载地址。
- `GET /public/legacy/audit?cursor=...&limit=50` 提供脱敏公开审计；事件不能包含联系人身份、邮箱、IP、设备或邮件错误。

**内容与交互**

- 页面依次展示发布说明、遗书正文、ZIP 元数据、下载按钮和脱敏审计时间线。
- 遗书正文只能渲染服务端返回的已清洗 HTML；禁止二次执行脚本、事件属性、外链 iframe 或原始 HTML。
- 设计稿中的“Copy Raw”改为“复制遗书正文”，复制当前可见纯文本；API 不提供原始 Markdown。
- “复制摘要”复制完整 SHA-256；“下载完整 ZIP”使用稳定的 `GET /public/legacy/package` 路由，支持 Range 与服务端限流。

**安全与验收**

- HTML 使用 `lang="zh-CN"`。所有英文状态和按钮需中文化，技术缩写如 SHA-256 可保留。
- 响应必须实际设置 `Cache-Control`、`X-Robots-Tag: noindex, nofollow, noarchive` 和同等 robots 元数据；页面上的可见文字不能替代响应头。
- 发布时间和审计时间转换为北京时间；ZIP 大小使用一致的二进制或十进制单位并注明。
- 下载失败不隐藏遗书正文；429 显示稍后重试，摘要仍可复制验证。

### 10.2 页面 13：公开遗书（移动端）

**目标与布局**

- 390px 设计稿将发布说明、遗书、ZIP 和审计纵向排列；必须展示与桌面端完全相同的正文和审计数据，不能因移动视口截断内容。
- 长摘要允许换行但复制值保持原样；下载按钮固定在内容流中，不遮挡审计时间线。

**交互与验收**

- 数据、安全头、清洗、下载和时间规则与页面 12 一致。
- 公开审计按游标加载，“加载更多”失败保留已加载事件；不得用无限滚动阻止用户到达页脚。
- ZIP 体积较大时在下载前明确显示大小，并提示移动网络流量；提示不阻止用户继续。
- 320px 宽度、200% 缩放和长遗书正文下无横向滚动或内容遮挡。

## 11. 邮件模板

### 11.1 页面 14：第二阶段管理员提醒邮件

**模板用途**

- 设计稿对应产品需求 7.6 的第二阶段管理员提醒，模板代码建议为 `DEATH_STAGE2_REMINDER`。
- 收件人是管理员主邮箱；主邮箱明确投递失败时，同一次逻辑通知立即尝试备用邮箱。

**变量与内容**

| 变量 | 必填 | 规则 |
|---|---|---|
| `{remaining}` | 是 | Worker 发送时计算的剩余时长文本 |
| `{release_at}` | 是 | `YYYY-MM-DD HH:mm:ss（北京时间）` |
| `{action_url}` | 是 | 仅进入网站，不直接终止流程 |

- 主题：`【紧急】数字遗产将在 {remaining} 后公开`。
- 正文必须说明已达到门限、准确发布时间、发送时剩余时间、需要在网站输入主密码，以及紧急联系人不能在第二阶段干预。
- CTA 使用“进入网站终止流程”，按钮后必须同时提供完整纯文本 URL。

**邮件验收**

- 邮件客户端不会可靠执行 JavaScript，设计稿中的动态倒计时必须删除；邮件只显示发送时的静态 `{remaining}`，点击后由网页展示实时倒计时。
- 关键 CSS 内联，正文宽度约 600px，在 320px 邮件视口可读；禁用外部字体不影响信息层级。
- 不使用跟踪像素，不把密码、令牌或内部工作流 ID写入可见正文。入口如需令牌，按 API 约束放在 URL Fragment。
- 预览使用 `POST /owner/email-templates/{templateCode}/preview`，预览不发送邮件。

### 11.2 页面 15：紧急联系人首次确认邮件

**模板用途**

- 设计稿对应产品需求 7.3 的首次死亡确认请求，模板代码建议为 `DEATH_CONFIRMATION_REQUEST`。
- 每位工作流快照联系人收到独立投递；某个联系人失败不影响其他联系人，也不披露收件人名单。

**变量与内容**

| 变量 | 必填 | 规则 |
|---|---|---|
| `{owner_name}` | 是 | 经过 HTML 转义的管理员显示姓名 |
| `{action_url}` | 是 | 邮件入口；链接本身不作出决定 |

- 主题：`【重要】请确认 {owner_name} 的联络状态`。
- 正文说明触发原因、两种可选决定、必须输入联系人姓名/密码/指定确认文字，以及首次确认没有自动到期时间。
- CTA 使用“进入确认页面”，按钮后同时提供完整纯文本 URL。

**邮件验收**

- `{owner_name}`、URL 和所有管理员可配置内容必须转义；不允许模板注入任意 HTML、脚本或未声明占位符。
- 入口令牌只用于定位流程，不增加权限。前端从 Fragment 读取后立即清除，并作为 `entryToken` 通过 `POST /auth/contact/login` 的请求体提交。
- 链接打开后仍需 `POST /auth/contact/login`；邮件打开、链接点击或扫描器访问都不能改变流程状态。
- 流程已进入第二阶段或被终止时，入口页显示操作已关闭，不允许提交旧决定。

## 12. 设计稿与实现基线差异

以下差异必须在编码时按右栏修正：

| 设计稿内容 | 实现基线 |
|---|---|
| 联系人状态 `PENDING` | 使用领域状态 `PENDING_KEYING`，中文显示“待分片” |
| 门限描述“超过 70%” | 达到 `ceil(N × 70%)` 即进入第二阶段 |

| 移动文件页固定最大 50MB、要求证明文件 | 容量由部署/API 返回；只强制根目录唯一 `will.md` |
| 页面时间显示 UTC | 所有用户界面和邮件显示北京时间 |
| 邮件 JavaScript 动态倒计时 | 邮件显示发送时静态剩余时间，网页负责实时倒计时 |

| 移动 viewport 禁止缩放 | 必须允许用户缩放以满足无障碍要求 |
| 第一阶段公开页显示联系人事件时间线 | 只显示聚合进度，不公开逐人事件或私有审计 |

## 13. 尚缺设计稿的必要页面

16 份现有设计稿已全部在本文覆盖，但完整产品仍需要以下独立页面或状态设计：

- 初始化管理员、部署令牌和启用清单；
- 管理员登录、忘记主密码请求与重置主密码；
- 联系人邀请注册、30 秒知情同意与 `PENDING_KEYING` 完成页；
- 联系人登录及首次确认的两种决定表单；
- 联系人旧密码修改；
- 主密码恢复的管理员与联系人流程；
- 未认证首页的 `NORMAL`、`PASSWORD_RECOVERY` 与公开 `RELEASE_PENDING` 变体；
- 私有审计详情、Legal、Privacy Policy、404、403 和通用错误页；
- 上传中断恢复、发布处理中与发布失败的运维状态页。

这些缺口不能用现有 16 份静态页面推断出未经确认的高风险交互；补充设计时继续遵守本文的全局规则和已有 API 契约。

## 14. 页面级验收清单

每个网页或邮件合入前至少验证：

1. 页面角色、状态守卫和路由与第 2 节一致；未授权时没有私有数据闪现。
2. 页面没有硬编码演示姓名、邮箱、时间、摘要、人数、版本号或倒计时。
3. 时间均以北京时间展示，倒计时从服务端时间校准。
4. 成功、空数据、加载、离线、401、403、409/423、422、429 和 5xx 状态有明确行为。
5. 密码、令牌、密钥、分片和私人审计不进入 URL、持久化浏览器存储、日志或分析系统。
6. 移动与桌面变体共享数据模型、权限、校验和提交逻辑。
7. 键盘、触屏、200% 缩放和屏幕阅读器能够完成核心流程。
8. 高风险提交具有重新认证、意图确认、幂等和服务端最终状态校验。
9. 公开页和邮件不泄露联系人身份或内部错误，公开遗书只渲染已清洗内容。
10. 对应设计稿的 HTML 和截图均可从第 2 节打开，页面名称、状态与实现一致。
