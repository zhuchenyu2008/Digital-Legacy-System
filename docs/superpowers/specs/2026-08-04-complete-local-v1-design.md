# Digital Legacy System 完整本地 V1 设计

> 文档状态：设计已逐段确认，待用户书面审阅
> 记录日期：2026-08-04（北京时间）
> 目标环境：Windows Docker Desktop 本地开发与验收；Linux Docker 后续部署
> 业务时区：`Asia/Shanghai`

## 1. 已确认目标

本次交付实现完整本地 V1，而不是静态演示或仅可启动的工程骨架。Web、API、Worker、数据库、对象存储、邮件沙箱、真实密码协议、数据库迁移、部署模板和自动化测试都必须可运行。

本地环境使用 PostgreSQL、MinIO 和 Mailpit，不连接真实 SMTP、正式 S3、真实个人资料、真实遗书或正式公开地址。所有能在本地自动执行的测试与验收项均为交付门禁；法律审查、密码学专家评审、人工渗透测试等外部事项继续作为生产上线阻塞项。

容器镜像必须保持 Linux 兼容。仓库同时交付生产版 Compose、Caddy、Secret 文件示例、迁移与部署脚本及 Runbook，但本次不接入真实域名、SMTP、S3，也不执行生产发布。

## 2. 架构方案

系统采用 TypeScript 模块化单体单仓库。HTTP API、后台任务和页面分进程运行，共享纯领域规则、应用用例、密码协议、持久化边界和接口契约。业务事实只通过 PostgreSQL 事务推进；跨事务副作用先写入 Outbox 或持久化任务，不依赖进程内定时器或内存事件。

```text
apps/
  web/             Next.js 中文响应式界面、浏览器密码学
  api/             NestJS HTTP API、认证授权、业务入口
  worker/          NestJS 后台任务、邮件、调度和发布

packages/
  domain/          纯状态机、门限和北京时间规则
  application/     API 与 Worker 共用的业务用例
  crypto/          版本化密码协议及浏览器/Node 实现
  persistence/     PostgreSQL 事务、仓储、锁和任务持久化
  contracts/       DTO、错误码、事件及 OpenAPI 类型
  email-templates/ 中文邮件模板
  test-fixtures/   密码学向量和合成测试数据

migrations/        SQL 迁移、数据库角色、约束和触发器
infra/             Compose、Caddy、Secret、迁移和部署脚本
tests/             集成、并发、E2E、安全和无障碍测试
```

使用 `pnpm workspace` 管理依赖，并提交锁文件。2026-08-04 的初始工具链基线固定如下；任何升级都必须由锁文件、变更记录和完整门禁验证驱动，不允许使用 `latest`、浮动镜像标签或未锁定依赖。

## 3. 本地与部署运行拓扑

本地 Compose 启动 Caddy、Web、API、Worker、PostgreSQL、MinIO 和 Mailpit。浏览器只通过 Caddy 访问 Web/API；API 在数据库事务中修改状态并写入 Outbox；Worker 从 PostgreSQL 领取任务，再调用 SMTP 或对象存储适配器。所有截止和并发裁决使用 PostgreSQL 时间与行锁。

开发配置支持 Web/API/Worker 热更新。验收配置使用与 Linux 部署相同的非 root 容器镜像和 Secret 文件挂载方式。生产模板只替换 Secret、SMTP、S3、域名和 TLS 配置，不改变领域代码、密码协议或状态机。

## 4. 密码学实现设计

密码学实现遵循现有[系统架构](../../02-system-architecture.md)和[安全与隐私设计](../../05-security-privacy.md)，本节固定本次完整本地 V1 的实现边界。所有协议都带显式 `protocolVersion`、算法版本、KDF 参数和长度前缀 AAD；认证失败对外使用不可枚举的统一错误。

### 4.1 密钥层级

| 材料 | 生成/输入位置 | 用途 | 持久化边界 |
|---|---|---|---|
| `MP` | 管理员输入 | 认证、签到、终止、派生 `OWNER_KEK` | 仅保存带 pepper 的 Argon2id PHC 验证值 |
| `CKP` | 联系人输入 | 联系人认证、派生 `CONTACT_KEK` | 仅保存带 pepper 的 Argon2id PHC 验证值 |
| `VK` | 管理员浏览器 CSPRNG | 保险库根密钥，包装各版本 `DEK_v` | 仅保存密码包装、加密分片或阶段包装 |
| `DEK_v` | 管理员浏览器 CSPRNG | 加密第 v 版 ZIP | 由 `VK` 使用 XChaCha20-Poly1305 包装 |
| `OWNER_KEK` | 浏览器由 `MP` 派生 | 包装/解开 `VK` | 不持久化 |
| `CONTACT_KEK` | 浏览器由 `CKP` 派生 | 包装/解开联系人私钥 | 不持久化 |
| `CPK/CSK` | 联系人浏览器 | X25519 sealed box 接收分片 | 公钥明文；私钥只保存密码包装 |
| `RELEASE_STAGE_KEK` | 部署时独立生成 | 包装发布等待阶段临时 `VK` | 只读 Secret，仅 Worker 可读 |
| `RECOVERY_STAGE_KEK` | 部署时独立生成 | 包装密码恢复阶段临时 `VK` | 只读 Secret，仅 API 可读 |

密码规范化统一使用 Unicode NFC 和 UTF-8，不裁剪、不大小写折叠、不静默截断。认证哈希与浏览器密钥派生使用不同盐、用途标签和输出；服务端 pepper 永远不发送给浏览器。实现使用受维护的 Argon2id、libsodium XChaCha20-Poly1305/secretstream/X25519，以及经过安全评审且支持 32 字节秘密的门限秘密共享库，不自行实现密码算法。

### 4.2 保险库和联系人建钥

管理员浏览器生成 256 位 `VK`，由 `MP` 派生的 `OWNER_KEK` 包装后上传。数据库同时保存 `vkCommitment` 和版本化包装元数据，但不保存 `MP`、`OWNER_KEK` 或明文 `VK`。

联系人注册时在浏览器生成 `CPK/CSK`。`CKP` 派生 `CONTACT_KEK` 并包装 `CSK`；服务端仅保存公钥、私钥包装和认证验证值。联系人修改密码时只重新包装 `CSK`，历史分片保持有效。

联系人列表达到启用条件后，管理员浏览器解开 `VK`，分别生成死亡发布和主密码恢复两套分片。两套分片使用独立随机多项式、用途标签、承诺和门限；每份分片绑定 `vaultId`、`generationId`、`contactId`、`shareIndex` 和 `purpose`，再以对应 `CPK` sealed-box 加密。分片代次只有在服务端验证承诺、成员快照和 `vkCommitment` 后才能原子激活。

### 4.3 ZIP 加密和版本激活

管理员浏览器先做体验性 ZIP/`will.md` 检查，再生成独立 `DEK_v`，通过 libsodium secretstream 分块加密 ZIP，最后一块必须带 `TAG_FINAL`。`DEK_v` 由 `VK` 包装并绑定包 ID、版本、算法版本和密文摘要。

密文进入 MinIO 私有桶。完成上传时，服务端必须从对象存储重新读取实际对象，计算大小和 SHA-256，并校验 manifest、secretstream 头和协议绑定；不能信任客户端自报摘要。只有完整验证通过的新版本才能在数据库事务中原子激活，旧密文在事务提交后异步删除，旧版本摘要和审计记录保留。

### 4.4 死亡确认与最终发布

流程开始时锁定联系人和分片代次快照。联系人在浏览器使用 `CKP` 解开 `CSK` 和自己的死亡发布分片，API 只在认证及确认事务成功后接收该流程的临时分片。

达到 `ceil(N × 70%)` 门限的事务取得流程行锁，验证分片承诺并重建 `VK`。明文 `VK` 只存在于受控内存窗口，随后立即由 `RELEASE_STAGE_KEK` 包装；流程分片和其他明文缓冲区被销毁，状态原子进入 24 小时 `RELEASE_PENDING`。

管理员在截止前使用正确 `MP` 终止时，系统删除阶段包装并回到 `ARMED`。截止事务成功取得发布锁后，任何终止请求永久失败。Worker 使用 `RELEASE_STAGE_KEK` 解开 `VK` 和当前 `DEK_v`，流式验证并解密 ZIP，在隔离临时目录内安全读取根目录唯一 `will.md`，生成清洗后的公开 HTML、明文 ZIP、摘要和脱敏审计。任何认证、ZIP 安全或完整性失败都保持发布锁并进入可观测重试，不输出部分内容，也不恢复取消能力。

### 4.5 主密码门限恢复

恢复流程使用独立恢复分片和 `floor(N ÷ 2) + 1` 门限。达到门限后，API 重建并使用 `RECOVERY_STAGE_KEK` 临时包装 `VK`。只有同时持有主邮箱单次链接、未消费的 8 位验证码和一次性浏览器 X25519 临时密钥对的会话，才能取得 sealed-box 加密的 `VK` 并用新主密码重新包装。

联系人不能看到 `VK` 或新主密码。恢复成功、取消或 7 天过期后销毁分片、令牌、验证码、阶段包装和临时密钥。恢复流程不暂停未签到截止；死亡确认先到时恢复立即取消。

### 4.6 信任边界和强制不变量

- 门限前，只有数据库、私有对象桶和部署 Secret 的攻击者不能恢复 `VK`；该保证不覆盖已控制线上 JavaScript、用户设备或达到门限后的服务器。
- 达到死亡或恢复门限后，服务器在受控窗口内具备解密能力，产品和文案不得称为端到端零知识。
- API 不得读取 `RELEASE_STAGE_KEK`；Worker 不得读取 `RECOVERY_STAGE_KEK`，错误权限配置必须拒绝启动。
- 密码、明文密钥、私钥、分片、Cookie、令牌和遗书正文不得进入 URL、日志、任务参数、错误响应或持久化浏览器存储。
- 浏览器中的清零只能尽力覆盖缓冲区，不能承诺 JavaScript 垃圾回收后的物理内存擦除。
- 所有密码学路径必须有固定向量、交叉运行时兼容、损坏/截断/错序、错误用途、错误代次和少于门限的负向测试。

## 5. 领域模块与业务数据流

### 5.1 领域边界

| 模块 | 职责 | 不承担的职责 |
|---|---|---|
| `Identity` | 管理员/联系人认证、会话、改密和重新认证 | 不推进死亡或发布流程 |
| `CheckIn` | 北京时间自然日签到、截止时间和提醒计划 | 不直接发送邮件 |
| `Contacts` | 邀请、知情同意、注册、删除和分片代次变更 | 不公开联系人名册或确认明细 |
| `Vault` | 保险库、ZIP 上传、校验、激活和旧密文清理 | 不决定发布时机 |
| `Workflow` | 死亡确认、24 小时等待、管理员终止和密码恢复 | 不直接调用 SMTP 或对象存储 |
| `Notification` | 邮件模板、幂等投递、主/备用邮箱回退和重试 | 不以投递结果推进业务状态 |
| `Publication` | 发布锁、解密、ZIP 安全检查、公开页面和下载 | 不提供发布后的撤回或替换能力 |
| `Audit` | 私有链式审计和公开脱敏时间线 | 不保存密码、密钥、分片或遗书正文 |
| `TestMode` | 测试命名空间、测试时钟、白名单和对象前缀 | 不读写正式流程或正式公开地址 |

### 5.2 命令处理路径

所有写操作遵循同一条路径：

```text
HTTP 命令
  -> 身份、CSRF、重认证和幂等校验
  -> PostgreSQL 事务与必要行锁
  -> 纯领域规则作出状态决定
  -> 同事务写业务状态、私有审计和 Outbox
  -> 提交事务
  -> Worker 执行邮件、对象存储或发布副作用
```

领域包只接收显式输入并返回决定、事件或错误，不读取系统时间、网络、环境变量或数据库。应用包负责取得数据库时间、加载聚合、调用领域规则并协调事务。持久化包实现锁、仓储、Outbox 和幂等记录。API 与 Worker 只负责传输、调度和适配器边界。

业务状态、审计事件和待执行副作用必须在同一事务内形成一致结果。任何不能与业务状态同事务提交的操作都先记录为 Outbox；邮件成功、对象路径或浏览器倒计时不能直接成为状态迁移依据。

### 5.3 查询与旧任务退出

查询接口使用显式查询模型，只返回当前角色允许看到的字段。门限、截止、剩余人数、公开状态和倒计时起点由服务端基于数据库事实计算，前端不得自行推进状态。

Worker 每次执行任务都重新读取流程 ID、状态版本、计划版本和当前数据库时间。签到后遗留的提醒、已取消流程的确认邮件、旧分片代次任务和重复发布任务必须通过版本与幂等键无副作用退出。进程重启后任务从 PostgreSQL 重新领取，不依赖内存中的完成标记。

### 5.4 测试模式隔离

测试流程使用独立记录或带数据库强制约束的 `TEST` 命名空间、独立 MinIO 前缀、Mailpit/SMTP 白名单和不可写正式地址。测试时钟仅注入测试应用服务，正式流程始终使用 PostgreSQL 当前时间。任何缺失测试前缀、收件人不在白名单或目标指向正式公开位置的测试副作用都必须在适配器入口拒绝。

## 6. 并发裁决、错误处理与故障恢复

### 6.1 并发和流程优先级

关键状态迁移使用 PostgreSQL `SELECT ... FOR UPDATE` 或带 `state`、`version` 条件的原子更新。流程快照固定联系人集合、门限、分片代次和活动包版本，流程活动期间禁止通过外部修改改变分母或发布内容。

同一事务中多个条件同时满足时按以下顺序裁决：

1. 已处于 `RELEASED`，或数据库当前时间已经达到 `release_at` 的发布；
2. 截止前管理员使用正确主密码终止；
3. `DEATH_CONFIRMING` 阶段联系人确认管理员仍然健在；
4. 肯定确认达到 70% 门限；
5. 未签到截止触发死亡确认；
6. 主密码恢复。

该顺序不撤销已经提交的事务。`release_at <= clock_timestamp()` 或 `publish_locked_at` 已设置后，即使 Worker 尚未完成解密，终止也永久拒绝。发布失败保持发布锁并持续重试，不能回退到可取消状态。

### 6.2 API 错误和并发契约

所有错误返回稳定错误码、可操作中文文案和 `requestId`。生产响应不包含调用栈、SQL、对象键、SMTP 原始响应、内部主机名或密码学材料。

| HTTP | 语义 |
|---:|---|
| `400` | 请求格式或确认文字错误 |
| `401` | 未认证或不可枚举的凭据错误 |
| `403` | 角色、CSRF、重新认证或快照权限不足 |
| `404` | 资源不存在；无权资源同样隐藏 |
| `409` | 状态、版本、唯一约束或幂等载荷冲突 |
| `410` | 邀请、验证码或单次令牌过期/已消费 |
| `413` | 超过部署容量上限 |
| `422` | ZIP、密钥材料或业务语义校验失败 |
| `423` | 认证或流程暂时锁定 |
| `429` | 速率限制 |
| `500` | 已脱敏内部错误 |
| `503` | 数据库或对象存储暂不可用 |

可编辑资源返回 `ETag`，更新要求匹配 `If-Match`。相同身份、接口和 `Idempotency-Key` 在有效期内以相同载荷重放时返回首次结果；相同键和不同载荷返回 `409`。联系人决定、包激活、门限迁移和发布锁还必须有数据库唯一约束或条件更新保护，不能只依赖幂等记录。

### 6.3 故障恢复语义

| 故障 | 必须行为 |
|---|---|
| API 重启 | 未提交事务回滚；已提交事实保留；客户端可用幂等键重试 |
| Worker 重启 | PostgreSQL 任务重新领取；幂等约束阻止重复可见副作用 |
| PostgreSQL 不可用 | 禁止以内存状态推进；恢复后按持久化截止时间补偿扫描 |
| MinIO 上传失败 | 新包不得激活，旧包继续有效 |
| SMTP 不可用 | 按固定序列重试，不阻塞最终公开 |
| 主邮箱明确失败 | 同一逻辑通知立即尝试备用邮箱，不消耗外层重试次数 |
| 发布解密/完整性失败 | 保持发布锁；公开显示“发布处理中”；私有日志和审计记录原因 |
| 第二阶段服务器重启 | 使用 `RELEASE_STAGE_KEK` 恢复包装的 `VK` 和持久化倒计时 |
| 阶段密钥丢失 | 对应活动流程不可恢复；健康检查和 Runbook 明确报告，不伪造成功 |
| 系统时钟跳变 | 以 PostgreSQL UTC 时间为准，Worker 补偿过期任务 |

错误日志采用结构化 JSON 并包含 `requestId` 或 `jobId`。健康接口区分进程存活、依赖就绪和管理员私有运维详情；公开健康接口不暴露版本、队列数量、依赖地址或内部错误。

## 7. 页面、接口契约与用户体验

### 7.1 页面范围和视觉优先级

生产 Web 实现 `前端设计` 目录中的 16 组视觉参考，以及页面规格补齐的初始化、管理员/联系人登录、联系人注册与确认、密码恢复、测试模式、审计和系统健康页面。移动端与桌面端共享路由、组件、状态和数据源，通过响应式布局适配，不维护两套业务实现。

视觉实现以现有截图和 HTML 为主要基线，尽量复现布局、配色、间距、图标、字体层级、信息密度和移动/桌面响应式效果。发生冲突时按以下顺序取舍：

1. 已确认的状态机、不可逆语义和角色隐私；
2. 密码、密钥、分片和令牌的安全边界；
3. 无障碍及关键流程可完成性；
4. 设计截图的视觉还原；
5. 静态 HTML 中的演示数据、演示功能和占位链接。

设计稿中的姓名、邮箱、时间、摘要、人数、版本和倒计时替换为服务端数据。与产品基线冲突的演示功能可以删除、禁用或改写。无意义的 `href="#"` 根据实际用途改为真实路由、按钮或不可用说明；没有产品依据的入口可以移除。

### 7.2 路由与状态来源

```text
/setup、/login
/admin、/admin/contacts、/admin/files、/admin/settings
/admin/workflows/current、/admin/audit、/admin/system-health
/contact/register、/contact/login、/contact/workflows/current
/recovery/*
/simulations/*
/、/legacy
```

页面状态、门限、流程版本、截止时间和 `serverNow` 全部来自 API。客户端倒计时只用于展示并定期校时；归零后显示“发布处理中”，直到服务端返回 `RELEASED`。私有路由在渲染敏感内容前完成会话与角色守卫，不允许出现未授权数据闪现。

### 7.3 第三方静态资源和敏感页面边界

允许使用 Google Fonts、Material Symbols 等第三方静态 CDN，以提高设计稿还原度；必须提供系统字体或本地图标回退，CDN 失败不能阻断签到、终止、联系人确认、恢复或下载。可固定版本和完整性摘要的静态资源应固定版本并配置合理 CSP。

处理密码、`VK`、`DEK`、联系人私钥或 Shamir 分片的页面不得执行第三方运行时 JavaScript。Tailwind CDN 等运行时编译脚本不用于这些页面；样式在构建期产出。该限制不禁止字体、图标或纯样式静态资源，但部署文档必须说明第三方资源会产生外部请求和隐私元数据。

### 7.4 浏览器安全与可访问性

- 会话使用 HttpOnly Cookie；写操作使用 CSRF 和按接口要求的幂等键。
- 邮件入口令牌从 URL Fragment 读取后立即清除，再通过一次性接口消费。
- 密码、验证码、令牌、密钥、分片和敏感响应不得进入 URL、`localStorage`、分析事件或日志。
- 密码字段允许密码管理器；只有法定确认文字禁止粘贴、拖放和自动填充。
- 页面覆盖加载、空数据、离线、401、403、409/423、422、429 和 5xx 状态。
- 320px 宽度、200% 缩放、中文输入法、键盘、触屏和屏幕阅读器均可完成关键流程；主要点击区域至少 `44 × 44px`。
- 视觉回归以现有截图为基线，真实数据、无障碍和安全要求造成的差异必须在快照说明中记录。

### 7.5 OpenAPI 与邮件模板

API 统一使用 `/api/v1`。仓库提交 OpenAPI 3.1 文件，并生成 Web 使用的类型化客户端；CI 检查未声明路由、DTO 漂移、错误码漂移和客户端生成结果。页面不得重复手写接口类型或自行定义状态枚举。

邮件模板使用版本化中文文案和安全变量白名单。模板不允许脚本、表单、远程追踪像素或未声明变量，并在 Mailpit 中完成桌面与移动宽度验收。邮件链接只作为入口，除最终公开链接外不得直接改变业务状态。

## 8. 测试、交付物与完成标准

### 8.1 自动化测试门禁

测试按风险由内到外分层，并统一进入本地验收命令：

- 领域单元测试覆盖北京时间自然日、门限、状态机、任务幂等和所有边界值；
- 密码学测试覆盖固定向量、浏览器/Node 互操作、错误密钥、损坏、截断、乱序、代次和用途隔离；
- 数据库测试覆盖迁移、角色权限、约束、不可变触发器、事务回滚和迁移重复执行；
- 并发测试覆盖门限竞争、否定确认、管理员终止、发布截止、包激活和重复任务；
- API 契约测试覆盖 OpenAPI、角色矩阵、CSRF、幂等、乐观并发和错误码；
- 前端测试覆盖组件状态、响应式、键盘/触屏、无障碍和设计稿视觉回归；
- E2E 覆盖初始化到 `ARMED`、正常签到、死亡确认与取消、完整发布、密码恢复、SMTP/MinIO 故障和测试模式隔离；
- 容器验收覆盖 Windows Docker Desktop 冷启动、健康检查、迁移、进程重启恢复和 Linux 镜像冒烟。

测试只使用合成 ZIP、测试密码、Mailpit 收件人和 MinIO 测试对象。验收记录包含提交版本、迁移版本、北京时间、请求/任务关联 ID、预期结果、实际结果和证据路径。

### 8.2 交付物

仓库交付完整源代码、锁文件、SQL 迁移、数据库角色和触发器、Dockerfile、开发/验收/生产 Compose、Caddy 配置、OpenAPI、类型化客户端、Secret 示例与生成脚本、Mailpit/MinIO 配置、中文邮件模板、Runbook、测试命令和验收证据模板。

生产配置只提供可审阅模板，不包含真实域名、真实 SMTP/S3 凭据、正式个人资料或可触发真实发布的数据。Secret 示例只能包含文件名、格式和生成说明，不能提交可用默认密钥。

### 8.3 完成标准

在全新的 Windows Docker Desktop 环境中，仅生成本地 Secret 后即可通过仓库提供的 PowerShell 入口或等价 `docker compose` 命令完成构建、迁移和启动。所有容器通过健康检查，全部本地自动化门禁通过，完整发布和恢复流程可用合成数据演练，停止并重启容器后状态和持久化任务能够继续。

生产模板必须能在 Linux Docker 上完成配置预检、迁移和镜像启动冒烟。完成本地 V1 不代表真实域名、SMTP、S3、备份、MFA、法律审查、密码学专家评审或人工渗透测试已经完成；这些项目继续作为正式上线阻塞项。

## 9. 实施分解与规格来源

本文件是完整本地 V1 的总设计。现有产品、架构、数据库、API、安全、页面、运维和测试文档分别承担子系统详细规格，因此后续不把整个系统塞入一个不可审阅的超大任务。实施计划按以下可独立验收的工作包拆分，但最终在同一 V1 交付中集成：

1. 工具链、单仓库、容器、配置、OpenAPI 和健康骨架；
2. 领域规则、PostgreSQL 迁移、权限、事务和持久化任务；
3. 密码协议、固定向量、联系人密钥、保险库和 ZIP 流式加密；
4. 初始化、认证、签到、联系人与分片代次；
5. 死亡确认、密码恢复、通知、审计和不可逆发布；
6. 全部生产页面、邮件模板、设计稿还原和无障碍；
7. 测试模式、故障注入、E2E、安全回归、部署模板和 Runbook。

每个工作包必须以可运行、可测试且可由评审者独立拒绝或接受的交付物结束。后续工作包只能依赖前序工作包明确导出的接口，不能通过复制领域规则、数据库查询或密码协议绕过边界。
